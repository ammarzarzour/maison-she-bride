# Maison She Bride

متجر أزياء إلكتروني تجريبي مع واجهات المتجر والبائع والإدارة، متصل بـ Supabase.

## صفحات المشروع

- `index.html`: المتجر، البحث، الأقسام، المفضلة المحفوظة على الجهاز، فرز المنتجات حسب السعر والاسم، السلة، العربية والإنجليزية، وتبديل العملة. تعرض الواجهة 24 منتجاً في الصفحة مع أزرار تنقل ثنائية اللغة وتعيد الصفحة الأولى عند تغيير البحث أو التصنيف أو الفرز.
- `seller.html`: واجهة البائع.
- `admin.html`: إدارة المتاجر والمنتجات وحالات الطلبات والشحن والفواتير.
- **سلامة بيانات الكتالوج:** لا تُعرض دفعة تحتوي سعراً غير رقمي أو مخزوناً غير صحيح؛ تُظهر الواجهة خطأ بدلاً من سعر `NaN` أو كمية مضللة. الاختبارات في `tests/catalog.cjs` تغطي الحالات غير الصالحة.
- التحقق من أسعار وكميات مخزون الكتالوج يرفض القيم الفارغة و`null` والقيم المنطقية بدلاً من تحويلها ضمنياً إلى صفر؛ يغطي `tests/catalog.cjs` هذه الحالات.
- تُرفض كذلك مصفوفات JSON والكائنات الواردة في حقول السعر والمخزون حتى إن أمكن تحويلها رقمياً في JavaScript، مع اختبارات انحدار لهذه الحالات.
- يُرفض أي منتج بمعرّف فارغ أو مؤلف من مسافات بيضاء فقط، لحماية الربط بين بطاقة المنتج والسلة؛ تغطي الاختبارات هذه الحالات.
- المنتجات المنشورة تحتاج اسماً غير فارغ بالعربية والإنجليزية؛ إذا احتوى رد الكتالوج على عنوان ناقص أو غير نصي، يُرفض الرد بأكمله بدلاً من عرض اسم فارغ أو `undefined`. أُضيفت حالات اختبار لذلك.
- أسماء الأقسام كذلك يجب أن تكون نصوصاً غير فارغة بالعربية والإنجليزية؛ يرفض محمّل الأقسام النتائج غير المكتملة، وتغطي اختبارات `tests/categories-pagination.cjs` الأسماء المفقودة والفارغة.
- `catalog.js`: قراءة المنتجات والأقسام من Supabase على صفحات ثابتة من 100 عنصر حتى 1000 لكل نوع، مع رفض بيانات الأقسام المكررة أو الناقصة والنتائج الجزئية، وطلب تحقق إضافي عند اكتمال الحد. المنتجات: مع رفض النتائج الجزئية إذا فشلت صفحة لاحقة أو تكررت معرّفات المنتجات بين الصفحات أو وصلت بيانات ناقصة. يتحقق الكود بطلب إضافي محدود من اكتمال الكتالوج عند وجود 1000 منتج بالضبط؛ إذا تجاوز العدد 1000 يعرض خطأ بدلاً من إخفاء المنتجات الزائدة. تقسيم العرض إلى صفحات هو تقسيم داخل المتصفح فقط؛ ما زال جلب البيانات يقتصر على 1000 منتج، ويلزم ترقيم صفحات على مستوى الخادم للكتالوجات الأكبر. تُرفض كذلك الاستجابات التي تتجاوز حجم الصفحة المطلوب، لتجنب تخطي المنتجات.
- `sanad-preview.html` و`sanad-demo.js`: نموذج أولي لسند سوريا ضمن الاستضافة الحالية مؤقتاً؛ دليل خدمات ثنائي اللغة والبحث ومحاكاة إنشاء طلبات وهمية ومتابعة حالتها.
- `sanad-admin-preview.html` و`sanad-admin-demo.js`: لوحة متابعة تجريبية باللغتين لعرض الطلبات الوهمية من نفس المتصفح، إحصائيات الحالات وتحديثها أو حذفها محلياً. **ليست لوحة إدارة محمية ولا خدمة حكومية** ولا تُستخدم معها بيانات أشخاص حقيقية. لا يوجد تسجيل دخول أو إرسال طلبات أو بيانات إلى الخادم.
- `backend/`: ملفات قاعدة البيانات.
- `tests/smoke.cjs`: فحص JavaScript وصفحات الموقع الأساسي وسند سوريا وروابط الانتقال المختصرة للنموذج.
- `tests/storefront.cjs`: اختبار سلوك المفضلة والفرز واستعادة السلة، وتقسيم المنتجات إلى صفحات، وحدود التنقل وإعادة ضبطه عند البحث أو الفرز.
- `tests/storefront-preferences.cjs`: اختبار استعادة اللغة والعملة من إعدادات المتصفح، ورفض القيم المخزّنة غير الصالحة ومنع عرض `NaN`، ودعم اتجاه العرض العربي والإنجليزي.
- `tests/storefront-safety.cjs`: اختبار منع إدراج وسوم HTML أو خصائص غير مقصودة ضمن أسماء الأقسام وأزرار السلة في اللغتين.
- `tests/categories-pagination.cjs`: اختبار ترقيم صفحات الأقسام حتى حد 1000، ومنع تكرار المعرّفات أو الأسماء التقنية (slug) أو قبول أقسام ناقصة أو استجابات جزئية. يشمل أيضاً اختبار استجابة أكبر من الحد المطلوب.
- `tests/live-categories.cjs`: اختبار عرض أسماء الأقسام الفعلية من Supabase بالعربية والإنجليزية، والتصفية، وتحديث القائمة عند تغيّر الأقسام.
- `tests/catalog-images.cjs`: اختبار قبول روابط صور المنتجات HTTPS فقط، ورفض بيانات الصور غير الصحيحة قبل عرض الكتالوج.
- يتحقق محمّل صور المنتجات أيضاً من أن ترتيب الصورة `position` قيمة عددية صالحة أو نص رقمي غير فارغ، ويرفض المصفوفات والكائنات والقيم المنطقية والنصوص البيضاء؛ تُعامل القيمة `null` أو الحقل الغائب كترتيب افتراضي صفر للتوافق مع البيانات السابقة.
- `tests/catalog-refresh.cjs`: اختبار تحديث الكتالوج عند فشل جلب المنتجات أو الأقسام، وإخفاء البيانات القديمة مؤقتاً مع الحفاظ على السلة، ثم نجاح إعادة المحاولة.
- `tests/sanad.cjs` و`tests/sanad-admin.cjs`: اختبار تفاعلي لمحاكاة الطلبات الوهمية ولوحة متابعتها، والتحقق من بقاء البيانات محلياً وعدم وجود اتصال شبكي.
- `.github/workflows/smoke.yml`: تشغيل الاختبارات عند تحديث الفرع الرئيسي أو فتح Pull Request.

## فتح نموذج سند سوريا

- رابط النموذج المختصر على GitHub Pages: `https://ammarzarzour.github.io/maison-she-bride/sanad/`
- رابط لوحة المتابعة الوهمية: `https://ammarzarzour.github.io/maison-she-bride/sanad/admin.html`
- المساران داخل `sanad/` يعيدان توجيه المتصفح إلى صفحات النموذج الأصلية، ويوفران رابطاً يدوياً عند تعطيل التحويل التلقائي.
- النموذج **غير حكومي وغير صالح للطلبات الحقيقية**؛ البيانات الوهمية محلية في المتصفح. لا توجد مصادقة رسمية أو مدفوعات.
- نشر GitHub Pages مستقل عن نجاح اختبارات GitHub Actions؛ يجب التحقق من نتيجة مهمة `pages build and deployment` ومن فتح الرابط على متصفح فعلي. لا يوجد مستودع GitHub منفصل لسند بعد.

## حالة التشغيل

**الموقع ليس جاهزاً لاستقبال مبيعات حقيقية.**

- الكتالوج يعرض المنتجات المنشورة المتاحة من قاعدة البيانات؛ إذا كانت قاعدة البيانات خالية فلن تظهر منتجات. تظهر فلاتر الأقسام وأسماؤها المترجمة من بيانات Supabase الفعلية بعد نجاح التحميل، بدلاً من قائمة الأقسام الثابتة.
- إذا تعذّر تحميل المنتجات أو الأقسام، تُخفى البطاقات القديمة وتظهر رسالة فشل بدلاً من عرض معلومات مخزون قد تكون قديمة؛ تظل السلة التجريبية محفوظة على الجهاز حتى إعادة المحاولة.
- إذا أشار منتج إلى قسم غير موجود في نتيجة الأقسام، يرفض المتجر عرض الكتالوج بدلاً من تصنيفه خطأ ضمن «الكل»؛ تغطي اختبارات تحديث الكتالوج هذه الحالة.
- واجهة الكتالوج ترمّز النصوص غير الموثوقة من الأقسام ومعرّفات المنتجات عند إدراجها في HTML، بما يشمل أزرار السلة.
- السلة والمفضلة تجريبيتان ومحفوظتان محلياً في متصفح الجهاز، وإرسال الطلبات والدفع الإلكتروني غير مفعّلين.
- **اتفقنا على تأجيل الدفع الإلكتروني**، فلا يُفعّل أي تحصيل في النسخ الأولية.
- أسعار الصرف المعروضة تقريبية لأغراض العرض فقط وليست أسعار سوق مباشرة؛ لا تستخدم للتحصيل.
- إعداد اللغة والعملات المحفوظ على جهاز الزائر يقبل فقط الخيارات المعروضة؛ عند فساد الإعدادات تعود اللغة إلى اختيار الجهاز والعملة إلى `SYP` بدلاً من إظهار أسعار غير رقمية. التحويلات المعروضة تجريبية.
- لا بد من إعداد حساب مدير بصلاحية `admin` من بيانات التطبيق الموثوقة في Supabase.
- لا تضع مفتاح `service_role` أو أي مفاتيح سرية في ملفات الواجهة أو GitHub.
- لا تستخدم بيانات عملاء حقيقية للاختبار.

## متطلبات الإطلاق التجاري

1. إنشاء حساب إدارة موثّق وتحديد صلاحيات البائعين.
2. رفع منتجات حقيقية مع صور وأسعار ومخزون دقيق، واختبار ظهورها على الموقع.
3. إنشاء مسار آمن لإتمام الطلبات من الخادم مع التحقق من السعر والمخزون وعدم تكرار الطلبات.
4. اعتماد سياسة حجز وتحديث المخزون وإلغاء الطلبات والاسترجاع.
5. ربط مزود دفع مرخّص، وتفعيل تأكيد الدفع من الخادم عبر Webhook موثوق، وعدم اعتبار واجهة العميل إثباتاً للدفع.
6. توفير أسعار صرف معتمدة أو أسعار مستقلة لكل عملة، مع توضيح العملة السورية الجديدة دون استخدام سعر افتراضي للتحصيل.
7. مراجعة الأمان وسياسات RLS وCORS والصلاحيات وحماية البيانات الشخصية.
8. اختبار رحلة شراء كاملة على الهاتف بالعربية والإنجليزية، واختبار الفواتير والشحن والاسترجاع.
9. إعداد سياسات الخصوصية والشحن والاستبدال والإرجاع والضرائب حسب أسواق التشغيل.

## الاختبارات

يمكن تشغيل الفحص المحلي باستخدام Node.js 22 أو أحدث:

```sh
node tests/smoke.cjs
node tests/storefront.cjs
node tests/storefront-preferences.cjs
node tests/storefront-safety.cjs
node tests/sanad.cjs
node tests/sanad-admin.cjs
node tests/catalog.cjs
node tests/catalog-images.cjs
node tests/categories-pagination.cjs
node tests/live-categories.cjs
node tests/catalog-refresh.cjs
```

الفحص الحالي يراجع صحة JavaScript في الصفحات وبعض شروط السلامة، **ولا يُعدّ اختبار شراء متكامل أو تدقيقاً أمنياً شاملاً**.

## نشر الموقع

يستخدم المشروع GitHub Pages للنشر الثابت. راجع نتيجة البناء في تبويب Actions، ثم اختبر الموقع المنشور على الهاتف. لا تُفعّل الدفع أو استقبال طلبات فعلية قبل إكمال قائمة الإطلاق.
